# Incident: Claude API returned 503 (unplanned)

| | |
|---|---|
| **Date** | 2026-11-09 |
| **Environment** | prod |
| **Type** | Unplanned, provider-side and transient |
| **Severity** | Low (one synthetic request) |

## Summary
At 22:15 SAST one request received HTTP 503 from the Anthropic API ("credential validation failed") and the agent returned a 500. The `triage-errors` and `slo-success-rate` alarms fired about 80 seconds later. No action was needed, and no further failures occurred.

| Measure | Time |

## Impact
One synthetic request returned a 500, so there was no triage result and no Case for it. No member impact, no data lost or exposed. The synthetic canary did not fire, because it needs 2 failures in an hour.

## Root cause
An error from the provider. The status was 503, not 401, and the same key succeeded on the other 628 requests that week, so it was not our credential. The cause inside Anthropic is not known.

## What went well
- Alarms fired within about 80 seconds, before anyone looked.
- The log line held the status and detail, so it was clear within a minute that it was a provider error and not our key.
- Salesforce and the rest of the service were unaffected.

## What didn't go well
- Provider errors are not queued and not sent to human review. A longer outage would return a 500 for every request until the kill switch was switched on. This is the known gap in the README.
- The 6-hour success-rate alarm stayed red for 6 hours after one failure. At about 25 requests per window, one failure is a 4% failure rate, which breaches a 99% target.
